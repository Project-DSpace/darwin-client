## What changes

This release is the pricing switch: the client settles at version 2 and pays each record by its size. A record's paid quote receives 3 × the median quote × the weight of the record's size class, rounded up, in place of 3 × the median quote for every record. A full 4 MiB chunk weighs exactly 1 and pays what it paid before; a smaller record pays less. How payments are made, read back and recovered doesn't change: per chunk, through the per-quote vault, with paid quotes read back, occupied quotes quoted and paid again, the price ceiling, payment recovery and envelopes by default, as in v0.3.11+ds.3.

This release was tested against darwin-node 0.23.0+ds.18 (`81dbac7`, node release 2, the revision its tests pin), which prices records by size. `vendor/ant-protocol` is that release's copy, the same tree.

### Paying by record size

- **The weight of a record** is the vendored `pricing::record_weight` of its data type and the size class of its bytes: w = 1/4 + 3/4 × (class top ÷ 4 MiB), held as an exact fraction. The size classes have power-of-two tops:

  | Class (record size up to) | Weight, in 1/1,024 of a full chunk | Share of a full chunk's amount |
  |---|---|---|
  | 16 KiB | 259 | 25.3% |
  | 32 KiB | 262 | 25.6% |
  | 64 KiB | 268 | 26.2% |
  | 128 KiB | 280 | 27.3% |
  | 256 KiB | 304 | 29.7% |
  | 512 KiB | 352 | 34.4% |
  | 1 MiB | 448 | 43.8% |
  | 2 MiB | 640 | 62.5% |
  | 4 MiB (a full chunk) | 1,024 | 100% |

  A record pays for the top of its class, so never less than in proportion to its size. A file under about 12.6 MB is three chunks of a third of its size, so the class edges people meet as file sizes are about 48 KB, 96 KB, 192 KB, 384 KB, 768 KB, 1.5 MB, 3 MB, 6 MB and 12 MB.
- **What pays by class.** `chunk_put`, the upload engine (files, data maps and envelopes) and `pointer_put` pay by the record's class. A pointer weighs as a record of its wire length, 5,303 bytes, whatever size a request declares: the 16 KiB class. `pay_for_storage`, which is given a size and no bytes, pays a chunk at a full chunk's amount, which every node accepts, and quotes and plans a pointer at its wire length.
- **The cost estimate** (`darwin file cost`) prices each chunk paid on its own by its class. Merkle payments stay refused on this network; the estimate prices merkle leaves at a full chunk's amount.
- **The price ceiling** (`--max-chunk-price`) still compares a quote's price, unchanged: a record costs at most 3 × the ceiling × its weight.
- **Occupied quotes** are handled as before: a record whose vault record isn't the client's payment (another rewards address, or less than the amount planned for it) is quoted again and paid again, up to 3 times.

### Settlement version 2

- **Every quote request declares settlement version 2** (`CURRENT_SETTLEMENT_VERSION`; `MIN_SUPPORTED_SETTLEMENT_VERSION` stays 1). A node at node release 2 quotes it at its weight total, the weights of its committed records added up; a node that predates release 2 answers `StorerUpdateRequired` and is skipped before anything is paid.
- **The unversioned quote retry is gone,** on the single-node and merkle paths: a node asked without a version quotes as for version 1 and would refuse the weighted payment made on that quote. A node that can't decode a versioned request is a peer that didn't quote.

### The band check

- A node of release 2 quotes `calculate_price(m)`, where m is its weight total, between floor(259/1,024 × K) and K for K committed records. So a quote's price is checked against a band, from `calculate_price` of the smallest weight's share of its committed key count to `calculate_price` of the count, in place of the exact price `calculate_price(K)`. The check is the same in native, merkle and browser quote checks. Every other check of a quote (its signature, its commitment and sidecar, its key cap) is unchanged.
- A node of full chunks has m = K and quotes exactly as before.

### Browsers

- **The browser core's own uploads** quote with `chunk_protocol` frames at `BROWSER_PROTOCOL_VERSION` whose `QuoteRequestV2` declares settlement version 2, so a node that prices by size quotes them by weight, and a node that predates it answers `StorerUpdateRequired`, which the core skips. They pay each record by its class.
- **A size-priced `quote_chunk` (the N+1 quote).** `BROWSER_QUOTE_PROTOCOL_VERSION`, one above `BROWSER_PROTOCOL_VERSION`, is used for a `quote_chunk` alone, and sent only to a node that advertises `size_priced_quote` in hello. Hello and reads stay at `BROWSER_PROTOCOL_VERSION`, so older nodes still serve reads. A `quote_chunk` at the next version that ends in a closed channel or an `invalid_request` answer (how darwin-node 0.23.0+ds.17 and older refuse a version they can't parse) fails as `unsupported_version`, with no quote, and the node is skipped, as a native client skips `StorerUpdateRequired`.
- **The fallback.** `verifyStorageQuote` takes an optional chunk length. Pass it only for a quote obtained by a size-priced `quote_chunk`: the amount is then the weighted amount for a chunk of that length. Without it, the amount is a full chunk's, which every node accepts, so a page that pays on any quote not obtained that way pays the full amount.

### Old clients and saved uploads

- **Old clients keep working at today's price.** A client that declares settlement version 1, or none, is quoted a full chunk's price and pays the full amount, which release-2 nodes always accept.
- **Saved uploads carry across the switch.** An upload checkpoint saved by an earlier release restores in this one: each saved plan is reused if its amounts equal the full amount or the weighted amount for the class of its own size, as from v0.3.11+ds.2, and a plan named by a pending payment attempt is settled exactly as recorded, from its journal and the chain. A test pins it: a checkpoint saved before the switch, with a journaled payment and a plan under 4 MiB, reconciles in this release with no new transaction.

### Library users: ant-protocol from the same tag

As in v0.3.11+ds.3, a project that uses `ant-core` takes both lines below, with the same tag:

```toml
[dependencies]
ant-core = { git = "https://github.com/Project-DSpace/darwin-client", tag = "v0.3.11+ds.4" }

[patch.crates-io]
ant-protocol = { git = "https://github.com/Project-DSpace/darwin-client", tag = "v0.3.11+ds.4" }
```

`SingleNodeQuotePayment::from_quotes` and the browser's `select_storage_quote` and `verify_storage_quote` take the record's weight, a `pricing::RecordWeight` (`RecordWeight::FULL` pays a full chunk's amount), and JavaScript's `verifyStorageQuote` takes the optional chunk length above. With the `devnet` feature, also repeat the `webrtc` patch from darwin-node at the `rev` in the tag's `Cargo.toml`.

## Releases

- **This release is published only after** the tagged commit's Test run (the end-to-end and browser tests, against darwin-node at its pinned revision) and its Build run on `main` both passed.
- **Nodes first.** A node older than release 2 is skipped for quotes, so this release stores only through release-2 nodes. Move to it once the nodes a service uploads through run node release 2.
- **Going back.** A revert is a re-pin to v0.3.11+ds.3, under the same pause used to move to this release: a service that takes `ant-core` by tag pauses its uploads, waits until nothing is unfinished, sets both lines' tags back, and resumes. v0.3.11+ds.3 settles at version 1 and pays the full amount, which release-2 nodes accept, and release-2 nodes keep accepting proofs paid at the weighted amount.
- **Uploads interrupted under this release** resume under v0.3.11+ds.3, whose restore accepts both amounts: a checkpoint saved by this release, with a journaled payment, restores there and reconciles with no new transaction. Where you can, finish an interrupted upload with this release before going back. Never delete a checkpoint that holds a pending payment attempt. A client older than v0.3.11+ds.2 stops with an error on a checkpoint written by v0.3.11+ds.2 or later, instead of paying again.
