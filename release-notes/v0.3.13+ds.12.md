## What changes

This release brings the client up to upstream's 0.3.13 (ant-core 0.15.0), with every change of ours kept: uploads still store an envelope by default and pay per chunk in DARWIN, at the same prices, with the same price ceiling, occupied-quote handling and payment recovery. It is tested against darwin-node 0.24.0+ds.22.

### Everyone using the client

- **Uploads report the file's SHA-256.** `darwin file upload` prints a `SHA-256:` line and adds `sha256` to its JSON. It is the hash of the file itself, whatever envelope stores it.
- **Manifests record and check it.** `darwin manifest create` records each file's SHA-256, `darwin manifest show` lists it, and extracting a manifest checks every downloaded file against it before the file takes its name. Manifests written before keep their bytes, and older clients read new ones, without the check.
- **Reads take a new first step.** After asking the node that served a chunk last, the client looks the chunk up by asking the nodes it finds on the way for it, rather than finding the nearest nodes first and asking them after. Today's nodes are asked with the messages they already know; nodes of a later release that announce the new get-or-closer request will be asked with it. A read still asks the bootstrap peers nearest the chunk, and still passes over a node that sends the wrong bytes.
- **First reads are spread** over the nodes that hold a chunk, rather than always going to the nearest.

### Browser pages

- **Manifests and links in the page:** `createManifest` and `createFileLink` build `.darwin` bytes and `darwin://` links without the network.
- **Pointer payments can be recovered.** `createPointer`, `updatePointer` and `transferPointer` take their payment callback with `{ onPrepared, onSubmission, onPaid }` options, no longer a bare function as their last argument. A page that loses its state after paying rebuilds the paid write with `recoverPointerPayment` from the checkpoint and the receipt, and stores it with `storePaidPointer`. Recovering pays nothing.

### Projects that take ant-core by git

- **Patch lines.** Repeat the `ant-protocol` and `saorsa-core` lines of `[patch.crates-io]` with this release's tag, as before; `ant-core` now requires exactly `ant-protocol` 6.0.0.
