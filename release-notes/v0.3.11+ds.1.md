## What changes

This is the first published release of the `darwin` client and of the `ant-core` library built from this repository. Prices, quotes and payments don't change, and the settlement version stays 1. Library users can take this release by its tag, with `ant-protocol` patched from the same tag (see "Library users" below).

This release was tested against darwin-node 0.23.0+ds.16, the first node release that refuses a browser session quickly when it is busy. It works with older nodes too: against them, browsers fall back to the full timeout and cooldown described below.

### Browsers: three random seeds, and busy nodes held off for 15 seconds

- **Three seeds, not all of them.** A browser keeps sessions with three seeds, taken in a random order. A seed whose dial fails or is declined is replaced by the next one. Three more are taken only when lookups through the first ones fall short, as on a network whose seeds know few of the other nodes. A seed's session stays open until the node closes it for idleness, so a seed that holds a record is read on the session already open.
- **Random order everywhere.** The `darwin` CLI tries its seeds in a random order after the peers it has cached, and so does a library client built from seeds. Client starts spread across every seed instead of landing on the first few listed.
- **A busy node is held off for 15 seconds.** The handling follows upstream ant-client #225, without its spreading of reads:
  - a dial that the node answers and declines counts as busy: an association that fails within 3 seconds of its connection checks starting, before they succeed, or one the node closes right after DTLS or during the handshake;
  - a busy node is held off for 15 seconds, and the browser tries the next seed. Every other failed dial keeps the 30-minute cooldown, including a DTLS failure after the connection checks succeeded, which means another node answered at that address;
  - `BrowserNetwork::refused_peers()` lists the peers held off as busy, with the time left;
  - a read whose possible holders are all busy waits for the first of them to come back, up to three times, then fails with "the nodes that may hold chunk ... are busy; try again shortly". Before, it reported the chunk as missing;
  - a busy node delays a read only while it could be among the record's nine nearest nodes.
- **When every seed is busy,** `connect()` says how many are.

### Reads ask fewer seeds

- **Before:** every chunk and pointer read asked the nine seeds nearest its address from the start, connected or not.
- **Now:** a read asks no seed before its lookup answers, apart from reading any peer already connected early. It then asks the seeds that are still among the nine nearest of everything it knows, or all nine nearest when the lookup found no peer. While the seeds are most of the network, they are most of every read's nearest nodes; as other nodes join, each read asks fewer of them.
- **Pointer reads** look up the record's close group first, and ask at least two seeds. `pointer_finality`'s census and read share that lookup.
- **Pointer reads and finality checks with busy peers.** A busy peer is left out of a lookup before it is asked, so farther peers can answer in its place. When a busy peer ranks in the close group and too few of the group answered, the result isn't reported as absent, open or at an older state: the read, census or finality check waits out the hold-off and runs again, up to three times, then fails as busy. A census whose every peer holds one final state, while a busy peer in the close group was never asked, reports the state as unconfirmed rather than final. The update and transfer checks before payment count busy peers in the same way. A native client holds no peer off, so its reads behave as before.

### Repeat reads: the last holder first, and a chunk cache sized by memory

- **Holders.** A client remembers which node served each chunk it read in the last 15 minutes, up to 1,024 chunks. A read of a chunk no longer in the cache asks that node first, and looks the chunk up only once the node answers without it, or hasn't answered within 1 second. The remembered node is only a hint: its answer never makes a chunk missing, and a node that no longer serves the chunk is forgotten. Reads with download diagnostics on work as before.
- **The default chunk cache** holds at most 1,024 chunks and at most an eighth of the memory free when the client is built, never less than one full chunk (4 MiB) and never more than 256 MiB. It evicts the least recently used chunks, and doesn't cache a chunk larger than its byte limit. It held 1,024 chunks whatever their size before, up to 4 GiB, which a long download on a small machine could fill. `ChunkCache::with_byte_budget` builds a cache with other limits, and `ChunkCache::new` a cache limited by chunk count alone, as before.

### The update message is darwin's own

- When nodes refuse this client's settlement version, the error now says which version the client settles under and the minimum the network requires, that no quote was issued and nothing was charged, and that a new `darwin` is built from https://github.com/Project-DSpace/darwin-client (see its README). Before, it repeated the node's wording, which pointed to `ant update`.
- **In a browser build,** whose code the page serves, the message says to reload the page.

### saorsa-transport 0.38.2

- The lock moves to saorsa-transport 0.38.2, and `ant-core` now requires at least 0.38.2. 0.38.1 kept every past QUIC connection's finished reader task allocated for as long as the endpoint lived; 0.38.2 reaps finished readers.
- A test (`lock_pins`) holds the committed lock to one saorsa-transport at 0.38.2 or later.

### Library users: ant-protocol from the same tag

A project that uses `ant-core` takes both lines below, with the same tag:

```toml
[dependencies]
ant-core = { git = "https://github.com/Project-DSpace/darwin-client", tag = "v0.3.11+ds.1" }

[patch.crates-io]
ant-protocol = { git = "https://github.com/Project-DSpace/darwin-client", tag = "v0.3.11+ds.1" }
```

- **The patch** puts this repository's `vendor/ant-protocol`, Autonomi's protocol crate with this network's price multiplier, in place of the crates.io release. Cargo applies a `[patch]` only in the top-level workspace, so taking `ant-core` alone isn't enough.
- **`ant-core` now requires exactly `ant-protocol` 5.0.0,** the vendored copy's version, so a newer crates.io release can't take the patch's place when the lock is made again. Without the patch, `ant-core` doesn't compile, rather than checking and paying quotes at Autonomi's prices.
- **With the `devnet` feature,** also repeat the repository's other patch, `webrtc` from darwin-node at the `rev` in the tag's `Cargo.toml`: `webrtc = { git = "https://github.com/Project-DSpace/darwin-node.git", rev = "<rev>" }`. `devnet` runs darwin-node in process, and darwin-node's patched `webrtc` cancels a DTLS handshake still in progress when a browser session closes; without the entry, the devnet's nodes are built with crates.io's `webrtc` 0.14.0. A build without `devnet` doesn't link `webrtc` at all, so it needs only the `ant-protocol` line.

### Also in this release

Earlier work on `main`, now in a published release for the first time:

- **New chunks go to their whole close group** (all seven nearest nodes), where library builds from before 15 October sent each chunk to four of the seven.
- **The node manager's own log** (`darwin-nodes daemon run --log-path PATH`) is written as `PATH.<UTC time>.log`, a new file every 10 MiB, every hour and at every start, and the family is kept within 50 MiB, with closed files older than a month deleted. At or below 1 GiB free on the log's partition it deletes its closed files and writes only warnings and errors, then says how many lines it left out once space returns. Node logs are never touched.

## Releases

- **This release is published only after** the tagged commit's Test run (the end-to-end and browser tests, against darwin-node at its pinned revision) and its Build run on `main` both passed. A client release is tested against a darwin-node revision on darwin-node's `main`, at or after node release 0.23.0+ds.16.
- **Going back.** A revert means installing the previous client. If you used the `darwin` CLI for an upload that was interrupted, finish it with this release before downgrading.
- **Checkpoints.** A checkpoint that holds a pending payment attempt is never deleted, and a journaled payment attempt is never quoted again.
