## What changes

This release gives the listings producer, `darwin listings serve`, three options its operator can set: a hide list of addresses it publishes nothing of, a hold that keeps each new readable entry out of the published files until its address is on a cleared list, and a held file listing the entries held. Hiding an entry that is already published starts the feed again under a new epoch without it, so the hidden address appears in no record; a new epoch can also be asked for with the new `darwin listings new-epoch`. Every option is off by default: a producer started as before publishes as before. Payments, uploads, downloads and the listings nodes serve are unchanged; the options change only what one producer publishes, and the network keeps every file and listing whatever its lists say.

### Producer operators: the hide list

- **`--hide-list FILE`.** An address on the list has no entry, support, row in `rejected.json` or feed record in any published file, nor in their `.gz` and `.zst` copies, and the producer stops reading its file's root map for a size.
- **The format.** One address per line, as 64 hex digits in any case, with or without `0x`; `#` starts a comment, to the end of its line, and blank lines are ignored. A line that isn't an address is skipped, and only its line number is logged. The cleared list uses the same format.
- **When it is read.** The file is looked at again at the start of each cycle and before each publication between cycles, and read again when its modification time or length changes. The last list read is kept in the producer's state: while the file is missing or can't be read, that list stays, after a restart too, with one warning for as long as it stays so.
- **Taking an address off.** An address removed from the list is decided again at the next cycle and, if listed, published at its own key, keeping its listing time, without waiting for the daily sweep. A producer started without `--hide-list` has an empty list, so what it hid before is published again.

### Producer operators: holding until cleared

- **`--hold-until-cleared FILE`** (needs `--held-file`). Each readable entry the producer hasn't published yet is held: it is published in no file until its address is on the cleared list. Once it is, the next cycle publishes it at its own key, keeping its listing time, with a feed put whose `at` is that publication's start. Like any late arrival, it may sit below `head.json`'s newest 50.
- **What stays.** Entries published before the option is set stay published, and entries that aren't readable are never held. An address on both lists is hidden. While entries are held, a readable address neither cleared nor published has no row in `rejected.json`, held or not.
- **Turning it off.** A producer started again without the option publishes the entries it held.

### Producer operators: the held file

- **`--held-file FILE`**, never inside the out dir (the producer refuses one there). It is written whole at every cycle, replacing the file at once, and on Unix is readable by its owner and group only.
- **What it holds.** `{"generated_at": …, "lists_read_at": …, "held": [...]}`: each entry held as its address's shard holds it, with its `data_map`, plus `held_since`, when the publication that first held it began. `lists_read_at` is the start of the latest cycle at which every list given could be read, changed or not, so whatever reads the file can tell how current the lists behind it are. Times are Unix seconds.
- **How long an entry stays.** An entry stays in the file, with the same `held_since`, across cycles and restarts, until it is published, hidden, or no longer served by the network.

### Producer operators: new epochs

- **`darwin listings new-epoch --state-dir DIR`** leaves a request, the file `new-epoch` in the producer's state directory. The producer's next cycle (or its first after it starts again) takes it once and removes it. It needs no network, wallet or chain, and a directory without the producer's `listings.mdb` is refused.
- **On hiding a published entry.** At the start of each cycle, once the lists are read, the producer starts a new epoch if an address on the hide list has an entry published. It checks what it holds, not what changed, so a list changed between cycles, or while the producer was stopped, is acted on too.
- **What a new epoch does.** The feed starts again at record 1, with one put for each entry kept (every published entry whose address isn't hidden), in key order, all with `at` set to when the epoch began. An entry not kept leaves the index with its support, and no record of the new epoch names it. Every file is written again, `status.json` last. Then the time pages the new `pages.json` doesn't list, with their copies, and the feed segments past the new last one are deleted at once, not a day later. A producer stopped part way finishes the deleting at its next start once the new epoch's files are in place, or after its next publication writes them. Entries held stay held.
- **Readers.** A reader following the feed sees the new `epoch` in `head.json`, or finds a page or segment missing, and starts again from `pages.json`, as `docs/listings-v1.md` has always said. No new removal reason is added.

### Library users

- **`ServeOptions`** (`hide_list`, `cleared_list`, `held_file`, all `None` by default), exported from `ant_core::data`, is given to the new `Producer::open_with`; `Producer::open` takes the defaults. A cleared list without a held file, or a held file inside the out dir, is refused.
- **`Producer::request_new_epoch`** leaves the request `darwin listings new-epoch` leaves (`listings_serve::NEW_EPOCH_FILE`), and **`Publisher::start_epoch`** starts a new epoch keeping the entries a given function keeps.
- **`ant_core::data::client::listings_lists`** holds the lists' format (`AddressList::parse`) and the held file's types.
- As before, a project that uses `ant-core` takes both lines below, with the same tag:

```toml
[dependencies]
ant-core = { git = "https://github.com/Project-DSpace/darwin-client", tag = "v0.3.11+ds.9" }

[patch.crates-io]
ant-protocol = { git = "https://github.com/Project-DSpace/darwin-client", tag = "v0.3.11+ds.9" }
```

### What stays

- Payments and their prices, size classes, the band, the price ceiling, V2 occupied-quote handling, the merkle refusal, payment recovery, kept proofs, root payments by default and envelopes by default, with all five payment fields shown, are those of v0.3.11+ds.8.
- The `listings/v1/` format is unchanged: the files, their fields and the feed's records are as before. Without the new options and without a `new-epoch` request, the producer publishes as v0.3.11+ds.8 does.

## Releases

- **It is tested against darwin-node 0.23.0+ds.20** (`363640e`), the revision its tests pin.
- **This release is published only after** the tagged commit's Test run and its Build run on `main` both passed.
- **Going back** to v0.3.11+ds.8 on the same state is a re-pin of both lines' tags, or a binary swap, under the usual pause. That version doesn't read the lists or the held entries, so it publishes again what they hid or held as it decides those addresses again, and it doesn't finish a new epoch's deleting that a stop cut short.
