## What changes

This release makes root payments the library's default: a `Client` given a wallet now pays through the root vault, DarwinRootVault at `0xf6675722f443132b045857546E57e35360Bb03b9` on Robinhood Chain, as the darwin CLI has since v0.3.11+ds.7, and `Client::without_root_payments` keeps today's payment vault, `0xE0f627986c0438De0E314B644f3C8aA21D3f4f6B` (Dan, 2026-10-29, on the recommendation that the library pay the root vault by default with an opt-out, outside payers staying opt-in: "do what you recommend"). An outside payer can also name its own address, so a root wave its wallet re-sent is counted in the upload's cost, and the CLI's readers on a devnet now read the root vault its manifest names. How root payments work, their proofs, the split between both vaults and the envelope rules are those of v0.3.11+ds.6; prices are those of v0.3.11+ds.5.

### Library users: root by default after upgrading

- **A client built from a key now pays the root vault.** After upgrading, a `Client` given a wallet (`Client::with_wallet`) pays every payment, of uploads, single records and pointers alike, through the root vault wherever the root vault of its network is known: the bundled network's, built in, or the one the client names with `Client::with_root_vault` (before or after `with_wallet`; on a devnet, the vault `ant_core::config::manifest_root_vault` reads from its manifest). Each payment's records go as one wave in one transaction, which the vault records once, and each record's proof (tag 0x03) shows its place in the wave. Where no root vault is known, the client pays the payment vault, as before. This applies to native builds; the browser core is unchanged.
- **One approval first.** The first root payment of a wallet is preceded by a one-time approval letting the root vault spend the wallet's DARWIN (one transaction, paid in gas), as the payment vault needed its own when the wallet first paid there. After that, payments cost the same tokens as before.
- **The root vault's wallet comes from the client's wallet.** The client pays the root vault through a wallet made from its wallet's own signer (`ant_core::config::root_wallet_of`), on the same RPC and token and signing for the same chain: the wallet `Client::with_root_payments_from_key` makes from the key. A wallet built from a `Wallet` value works as well as one built from a key string; no key needs to be passed again.
- **Opting out.** `Client::without_root_payments()` keeps every payment on the payment vault, one record kept by the vault for each quote paid, before or after `with_wallet`. The client still reads root-paid records at its network's root vault, or the one it names. `Client::with_root_payments` and `Client::with_root_payments_from_key` opt back in.
- **A wallet with its own transaction settings stays on the payment vault.** A wallet whose transaction settings were changed (`Wallet::set_transaction_config`, such as a gas cap) can't have them read and carried over to a second wallet, so such a client makes no root vault's wallet by default and pays the payment vault, as before. Give it one configured as its own with `Client::with_root_payments` to pay the root vault.
- **Root payments wait for the wallet's lock.** The root vault's wallet has a lock of its own (every `Wallet::new` makes one), so every payment the client sends, through either vault, also holds the lock of the wallet given to `with_wallet` (`Wallet::lock`, shared by its clones), after the key's lock the client keeps and before the root vault's wallet's own. A caller that pays with a clone of its wallet under that lock, as evmlib asks of a shared wallet, is serialised with the client's default root payments, as it was with per-quote payments, so the two never sign the same nonce. Don't call the client's payment methods while holding that lock. Merkle batch payments (`Client::pay_for_merkle_batch`) and the in-memory adapter's are now sent under the same locks.
- **A root vault's wallet the caller gives is kept.** `Client::with_root_payments` still takes a wallet of the caller's own, checked as in v0.3.11+ds.6, and a later `with_wallet` keeps it while it still matches.
- **Checkpoints and interrupted uploads.** An upload that plans a root payment writes its checkpoint in the second format of v0.3.11+ds.6, which v0.3.11+ds.5 and older clients refuse. A journaled root payment is reconciled only by a client paying the root vault, so resume an interrupted upload without `without_root_payments`.

### Outside payers: their own address

- **`UploadPayer::payer_address`** (none by default) names the address a payer's transactions are sent from. It matters only when another transaction than the one the payer returned recorded a root wave it paid: a recording sent from that address (its wallet sped the payment up or replaced it) counts the wave's total in the upload's cost, whether or not the returned transaction can still be read; one sent from another address, or whose sender can't be read, counts as moving no tokens. A payer that names none is counted as in v0.3.11+ds.7, by comparing the senders of both transactions.
- **Accounting only.** What is paid, and whether a wave counts as paid, are unchanged.
- **Root waves stay opt-in for outside payers**: `UploadPayer::pays_root_waves` stays false by default. Prepared uploads and chunks finished with `finalize_upload*` or `finalize_chunk`, other external signers, and a pointer's state quoted with `prepare_pointer_payment` stay on the payment vault, at settlement version 2, under the new default as well.

### CLI users: devnet readers

- **`darwin listings`, `darwin listing` and `darwin file verify` read the root vault** a devnet's manifest names (`evm.root_vault_address`), beside the payment vault, so they see records the CLI paid there. A manifest naming none reads the payment vault alone. On the bundled network they read both vaults, as before.
- **Payments are unchanged.** The CLI pays through the root vault by default, now through the library's default; `--no-root-payments` calls `Client::without_root_payments`, and a warning still says so when no root vault is known.

### What stays

- Size classes, the band, the price ceiling, V2 occupied-quote handling, the merkle refusal, payment recovery, kept proofs and envelopes by default, with all five payment fields shown, are unchanged.
- Payment reads on the bundled network keep the order of v0.3.11+ds.6: PublicNode, then Robinhood's RPC, then ordofi last.

### Library users: ant-protocol from the same tag

As before, a project that uses `ant-core` takes both lines below, with the same tag:

```toml
[dependencies]
ant-core = { git = "https://github.com/Project-DSpace/darwin-client", tag = "v0.3.11+ds.8" }

[patch.crates-io]
ant-protocol = { git = "https://github.com/Project-DSpace/darwin-client", tag = "v0.3.11+ds.8" }
```

## Releases

- **It is tested against darwin-node 0.23.0+ds.20** (`363640e`), the revision its tests pin, which settles under version 3.
- **This release is published only after** the tagged commit's Test run and its Build run on `main` both passed.
- **Going back** to v0.3.11+ds.7 is a re-pin of both lines' tags under the usual pause; a library client then pays the payment vault until it opts in with `with_root_payments` or `with_root_payments_from_key`, and an outside payer's `payer_address` is no longer called. An upload checkpoint holding a root payment is resumed there only by a client paying the root vault.
