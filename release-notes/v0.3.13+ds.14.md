## What changes

This release adds carried upload state, so an upload that one client paid to store and did not finish can be completed by another client without a second payment. It also replaces the bundled network's last payment-read RPC fallback with Tenderly's public gateway. Everything else is as in v0.3.13+ds.13.

### Carried upload state

As an example, a service pays to store an upload and stops before the upload finishes. The service passes the paid state from `UploadPayer::state_saved` to a second client, or to `darwin file upload <path> --carried <file>`. The second client stores the paid records without a second payment.

- **Where carried bytes come from.** The engine passes the upload's state to `UploadPayer::state_saved` after each checkpoint save, and once after taking a carried state. Calling `UploadState::checkpoint` writes the raw carried bytes. This is the only supported source of carried bytes. The `.msgpack` main checkpoint file in the client's data directory contains no proofs and is refused.
- **Three ways to supply a carried state.** An outside `UploadPayer` supplies carried bytes through `UploadPayer::carried_state` (`None` by default), which the engine calls once per upload immediately after opening the upload's saved checkpoint. A library wallet upload calls `Client::file_upload_carried` with `CarriedUploadOptions` (built with `CarriedUploadOptions::new(state)`). On the command line, `darwin file upload <path> --carried <file>` reads the raw bytes from `<file>` and calls `Client::file_upload_carried`. `darwin file upload --merkle` is still refused before the carried file is read.

### What the engine takes, settles, and refuses

- **Proofs taken and checkpoints unchanged.** The engine merges a carried state into the upload's checkpoint. It never replaces or deletes a saved checkpoint or a pending payment in it, so payment recovery does not change. A proof is added only to a record of this upload that has no local proof and is not marked as paid again and dropped. Proofs of records outside this upload are left out. The engine saves the merged state once before any payment, so an interrupted run resumes from the upload's checkpoint. On one machine, a carried lock named by the network and the records serialises carried uploads of the same file.
- **Unconfirmed payer payments.** A payer's unconfirmed payment in a carried state is settled through the new payer. The new payer receives the exact plans from that payment, as on any resume. That payment is left out if the upload's local state already contains the same payment, or if every record in that payment is already proved, marked as paid again, or pending locally. It is also left out if the local state proves one of its records with the quote that payment paid, because this upload already settled that payment and released any occupied quotes.
- **Records quoted again or paid again.** Unpaid quotes in a carried state are left out, and those records are quoted and paid again through the per-chunk path. Every taken record passes the same checks as a resumed record: quote signatures and identities, the price ceiling (`ClientConfig::max_chunk_price`), occupied-quote checks, payments in the network's token, and Merkle refusal. If no storer accepts a carried proof, that record is paid again at most once under the price ceiling and through the occupied-quote checks. A price ceiling below the network's quotes stops the upload when a record requires a new payment, as on any upload.
- **Private envelopes.** `UploadState` carries proofs and payments only, not the private envelope salt. A private envelope uses a new salt on the second client, so its envelope record is paid once more, alone in its payment.
- **Reported counts.** `FileUploadResult::carried` (`CarriedOutcome`, serialisable) counts the proofs in the carried state, the proofs taken, the records settled through the payer, the records paid again, and the records quoted again. `darwin file upload` prints the carried-state counts, and `--json` outputs them under `carried`.

The engine refuses a carried state whole with `Error::InvalidData` starting with `CARRIED_STATE_REFUSED` before anything is quoted, paid, or saved. A refusal pays nothing and leaves any saved checkpoint unchanged. A carried state is refused whole when it:

- fails `UploadState::restore` checks, such as a bad quote signature or a proof stored under another record's address;
- is a checkpoint's `.msgpack` main file without its proofs;
- names none of this upload's records;
- contains a Merkle proof or a pending Merkle batch;
- contains a wallet's unconfirmed payment (including a shared wave);
- contains a payer's unconfirmed payment passed to a wallet upload, or a payer's unconfirmed root-vault payment passed to a payer that does not pay root waves;
- contains an unconfirmed payment that names records outside this upload or pays a quote above `ClientConfig::max_chunk_price`;
- contains an unconfirmed payment that conflicts with a different pending payment already in the upload's checkpoint;
- contains an unconfirmed payment of which the upload's local state already includes some records and not others, without this upload having settled that payment.

### Payment-read RPC fallback

The bundled network's last payment-read fallback is now Tenderly's public gateway (`https://robinhood-chain.gateway.tenderly.co`) in place of ordofi's (`https://rpc.ordofi.network`), which refused every connection over 7 days up to 2026-11-24.

The provider order does not change. Payment reads go to PublicNode, then Robinhood's RPC, then Tenderly's gateway. Log queries go to Robinhood's RPC, then PublicNode, then Tenderly's gateway. Queried without a key on 2026-11-24, Tenderly's gateway answered calls at old blocks, JSON-RPC batches, and `eth_getLogs` on the payment vault over every span tried, up to the whole chain.

The exception that applied to ordofi is removed. Previously, a busy response (`-32005`) to a log query from ordofi did not trigger the provider hold-off, because ordofi returned `-32005` on spans wider than it served. That rule matched the bundled network's last log-query RPC and would have shifted to Tenderly's gateway, which did not return `-32005` in that way. A `-32005` busy response to a log query from any provider now triggers the provider hold-off, and the query moves to the next provider.

### Tests

Carried upload state is covered by 31 unit tests (28 in `ant-core` and 3 in `ant-cli`) and 8 end-to-end tests. A census test lists every payment path of the engine. It verifies whether a carried state covers each path, settles it through the payer, quotes it again, does not carry it, or refuses it, and verifies that the engine's refusal text matches the census wording.

### Known limits

- **One client at a time.** Uploads on different machines do not share a lock and are not serialised. Pass a carried state to one client at a time, and carry the newest state passed to `UploadPayer::state_saved`. Carried state bytes do not bind a network, while the carried lock and the upload's checkpoint are named by the network.
- **Narrow retry refusal after a dropped sibling proof.** One narrow sequence causes a refusal on retry. An upload takes a carried unconfirmed payment, releases one record because its quote is occupied, and confirms a sibling record. That sibling record then has its proof dropped and is marked as paid again, and the run stops before the new payment. A retry with the same carried state is then refused. The refusal pays nothing, and a run without the carried state resumes the upload from its saved checkpoint.
- **Not yet run on the live network.** Carried upload state has run on the end-to-end test networks (20 nodes with a local chain). It has not yet run live on the Darwin storage network.
- **Merkle proofs and batches are refused.** A carried state that contains a Merkle proof or a pending Merkle batch is refused whole.

## Releases

- **It is tested against darwin-node 0.24.0+ds.22**, the revision its tests pin, as v0.3.13+ds.13 is.
- **This release is published only after** the tagged commit's Test run and its Build run on `main` both passed.
- **Going back** to v0.3.13+ds.13 is a binary swap under the usual pause. That version does not read a carried state, and the `--carried` flag does not exist in that version.
