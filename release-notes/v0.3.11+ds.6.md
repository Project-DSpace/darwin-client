## What changes

This release is root payments: a client can pay through the root vault, DarwinRootVault at `0xf6675722f443132b045857546E57e35360Bb03b9` on Robinhood Chain, which keeps one record for a whole wave of records instead of one for each paid quote. It is opt-in: `darwin --root-payments`, or `Client::with_root_payments` in the library. Without it, every payment goes through today's payment vault, `0xE0f627986c0438De0E314B644f3C8aA21D3f4f6B`, as in v0.3.11+ds.5, and that vault stays the default. Prices are those of v0.3.11+ds.5: quotes on either price curve are accepted.

### Paying through the root vault

- **One wave a payment.** A payment's records are paid as one wave in one transaction (`payForQuotes`, the same call the payment vault takes). Each record's paid quote is a leaf, in ascending quote-hash order, and the vault records the wave once, under the key its tree gives, with a `RootPaid` log.
- **Each record's proof** (proof tag 0x03) carries its quotes, the transaction and its leaf: the paid quote's hash, the amount, the leaf's place in the wave, the wave's leaf count and its path. A storer hashes the leaf up the path to the wave's key and reads the vault's record under it.
- **Quotes and amounts.** A record paid through the root vault is quoted at settlement version 3, which means root proofs are accepted; a record paid through the payment vault is quoted at version 2, as before. Either way a record pays its size class's amount: 3 × the median quote × its weight.
- **Reading back.** Once the payment is confirmed, the client reads the vault's record of the wave back. If the wave's own transaction reverted or was replaced and the vault records the wave as paid by another transaction, its records are taken as paid, and their proofs name the transaction that recorded it, found by its `RootPaid` log. If that transaction can't be found, the payment fails with its journal kept, and a retry looks again without paying again.
- **Envelopes.** An upload's envelope is paid in the same wave as its content. Its payment record, with all five fields shown by default, is checked against the root vault and names the transaction that recorded the wave.
- **One signer at a time.** A root payment and a payment-vault payment from one key go through two wallets, so the client holds one lock for each key in the process while it signs and sends: the upload engine's journaled payments (a payment of its own, the lead of a shared wave and the reconciling of one), `Client::batch_pay`, the in-memory upload adapter's per-chunk payment and `Client::approve_token_spend`. The upload engine's journaled payments also hold the paying wallet's own lock (`Wallet::lock`) inside the key's lock, as before root payments. Three paths send without the key's lock, as before root payments: merkle batch payments (`Client::pay_for_merkle_batch`'s single batches and the in-memory adapter's `pay_merkle`), which the network's nodes refuse, and `SingleNodeQuotePayment::pay`, a raw building block. Separate processes with one key are not serialised.

### Falling back, record by record

- **A record whose close group holds a node that can't check a root proof** (one that answers `StorerUpdateRequired` at settlement version 3) is quoted again for today's payment vault and paid there. The client remembers such nodes, so later records near them are quoted for the payment vault at once.
- **A payment uses both vaults only when that saves gas:** when at least 3 of its records pay the root vault. Otherwise all of its records pay the payment vault. The envelope never pays alone in either payment.
- **Payers and external signers** (`file_upload_with_payer`, prepared uploads finished with `finalize_upload`, the browser core) pay quotes one by one, so their uploads are quoted for the payment vault, even on a client paying the root vault.

### What stays

- **Today's payment vault is the default and the network's identity.** Without `--root-payments`, quotes, payments, checkpoints and payment records are as in v0.3.11+ds.5.
- **Prices:** every quote check accepts a price on the current curve or on the earlier ×32 curve, as in v0.3.11+ds.5.
- Size classes, the band, the price ceiling, occupied-quote handling, the merkle refusal, payment recovery and envelopes by default are unchanged.

### Payment reads: ordofi last

On the bundled network, reads of payments (receipts, blocks and vault records) now go to PublicNode first, then Robinhood's own RPC, then ordofi. Log queries go to Robinhood's RPC first, then PublicNode, then ordofi, as before. ordofi stays as the last fallback rather than being dropped (Dan, 2026-10-28: "just keep it as last fallback"), and goes last for ordinary reads too (Dan, 2026-10-28: "Make it last"): it answered payment reads "busy" or too late in October 2026, and still answered -32005 "busy" on 28 October.

### Checkpoints

An upload checkpoint holding a plan or a proof for the root vault is written in a second format, which v0.3.11+ds.5 and older clients refuse whole; a checkpoint with neither is written as before. A journaled root payment is reconciled only by a client paying the root vault, so an interrupted `--root-payments` upload is resumed with `--root-payments`.

### Readers

Every reader of payments since v0.3.11+ds.3 reads the root vault beside the payment vault, so listings and upload proofs of root-paid records check out with them. Older readers (older CLIs, older darwin-listings, other indexers) report them as unpaid until they update.

### Library users: ant-protocol from the same tag

As before, a project that uses `ant-core` takes both lines below, with the same tag:

```toml
[dependencies]
ant-core = { git = "https://github.com/Project-DSpace/darwin-client", tag = "v0.3.11+ds.6" }

[patch.crates-io]
ant-protocol = { git = "https://github.com/Project-DSpace/darwin-client", tag = "v0.3.11+ds.6" }
```

`Client::with_root_payments` takes a wallet of the same key as `with_wallet`'s that pays the root vault (`ant_core::config::root_wallet` builds one); on the bundled network it must pay the root vault the configuration names. The vendored ant-protocol has root payment proofs (`PROOF_TAG_ROOT`, `ProofType::Root`, `RootPaymentProof`, `serialize_root_proof`, `deserialize_root_proof`) and `CURRENT_SETTLEMENT_VERSION` 3. `ProofType` is no longer `#[non_exhaustive]`, so a `match` on it names each type.
